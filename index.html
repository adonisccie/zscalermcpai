Think First · MCP & Security Model
What is the Model Context Protocol (MCP) and how does it let Claude Desktop call Zscaler APIs — without you writing any API or integration code?
See Model Answer

MCP (Model Context Protocol) is an open standard that lets AI models discover and invoke external "tools" at runtime. The Zscaler MCP server exposes Zscaler API calls as named tools (e.g., zpa_application_segment_list, zia_url_filtering_list). Claude Desktop loads the server, reads the tool catalogue, and when you submit a prompt, Claude decides which tool(s) to call, executes them through the MCP channel, and weaves the results into its response. You write no integration code — the MCP server handles authentication, pagination, and API formatting; you just prompt in plain English.

The extension is read-only by default. What additional mechanism protects write operations when you opt into them, and at exactly what point does explicit human accountability enter the loop?
See Model Answer

When write tools are enabled, the extension surfaces an HMAC confirmation prompt before any change is applied. This shows the exact proposed payload — tool name, target object, and every field being set — and requires your explicit approval. Human accountability enters the loop at this step: you see Claude's intent as a structured payload (not a natural-language description), and you approve or reject before anything changes in Zscaler. Rejecting requires no further action; approving is the authorisation record.

Task 1 — Install the Zscaler Extension in Claude Desktop

No terminal, no config files — GUI only.

Task 1.1 Open the Extensions directory

Anthropic and Zscaler ship the Zscaler MCP Server as a one-click Claude Desktop extension. No Docker, no terminal, no config files — just a few clicks and a credential prompt.

  1. Launch Claude Desktop.
  2. Open Settings → Connectors → Customize.
  3. Click Plus (+) icon → Browse Connectors to open the official directory.
  4. Search for Zscaler and select Zscaler MCP Server.
  5. Click Install. Claude Desktop downloads the bundle and opens the configuration screen automatically.
  6. Click Configure. Config Zscaler MCP Parameters.

Task 1.2 Enter your OneAPI credentials

The extension's configuration screen asks for four values. Paste each from the credentials you captured in the pre-lab setup. They are stored in your OS keychain — not a plaintext file.

Capture these four values first

Find them in Z Identity → Administration → API Key Management → OneAPI Credentials:

Client ID
Customer ID
  1. In the extension config screen, fill in:
    • Client ID: ZSCALER_CLIENT_ID
    • Client Secret: ZSCALER_CLIENT_SECRET
    • Customer ID: ZSCALER_CUSTOMER_ID —
    • Vanity Domain: ZSCALER_VANITY_DOMAIN —
  2. Click Save. Claude Desktop writes the values to your OS keychain.
⚠️ Warning

If any of the four fields are missing or incorrect, the extension will not authenticate. Stop and resolve with your instructor or Lab Team before proceeding.

Task 1.3 Scope the tools (recommended)

The configuration screen lets you choose which services and toolsets the extension exposes. Start narrow — you can broaden later. Scoping keeps Claude's context lean and reduces the chance of the wrong tool being chosen.

  1. In the extension config, set:
    • Services:
      zia, zpa
    • Toolsets:
      zia_url_filtering, zpa_app_segments, zia_url_categories
  2. Save. Leave Enable write tools set to OFF — you'll enable a narrow allowlist in Task 3 if you run the optional write task.
Note

Scoping is both a performance and a safety improvement. Without it, Claude must reason over hundreds of tools across all Zscaler services, slowing tool selection and increasing the risk of choosing the wrong one.

Task 2 — Operations Made Easy with Prompts

Task 2A Inventory — what do we have?

Run these three prompts in sequence. Notice you write no JSON, paginate nothing, and stitch no responses — Claude does that. Notice that results maybe varied depends on your Zscaler tenant configuration.

Prompt 1 — ZPA application segments

Using the Zscaler tools, list the first 10 ZPA application segments in our tenant. Show name, segment ID, and domain names. Format as a table.

Expected: Claude calls zpa_list_application_segments or zpa_get_application_segment, parses the response, and returns a clean table — the first "aha" moment vs portal clicking.

Prompt 2 — ZIA URL filtering rules

How many ZIA URL filtering rules do we have in total? Group the count by action (block / allow / caution), and tell me which rules are currently disabled.

Expected: A summary table plus a list of disabled rules — what would otherwise require opening every rule individually.

Prompt 3 — URL categories filtered by keyword

List ZIA URL categories whose name contains 'AI', 'social', or 'media'. For each, show the category name, type (predefined vs custom), and approximate URL count.

Expected: A focused list. Tests Claude's ability to filter at query time instead of dumping everything.

Task 3 (Optional) — One Guarded Write

Sandbox tenant only. Creates and deletes a test resource.

Task 3.1 Enable a narrow write tool
⚠️ Sandbox only

This task creates and then deletes a real config object. Do not run this on a tenant that serves real users. Specific options or settings maybe required and Instructor will guide you for this session

  1. Open Settings → Extensions → Zscaler MCP Server.
  2. Toggle on Enable write tools and set the allowlist to (you can specific the tools you want to allow or use * to allow all):
    zia_create_ssl_inspection_rule, zia_create_url_filtering_rule
    *
  3. Save, then fully quit and reopen Claude Desktop or even restart your Windows so the extension reloads with the new permissions.
Task 3.2 Create the test category
  1. In a new Claude Desktop conversation, enter:
    Create a new SSL inspection and URL filtering rule for username student. Show me what you intend to do and pause for confirmation before applying.
  2. Claude will propose the tool call, surface the HMAC confirmation prompt, and wait for your approval.
  3. Read the proposed payload carefully. Approve only after confirming it matches your intent exactly.
Note

The HMAC confirmation shows the exact payload — tool name, target object, every field being set. This is the most important security control in the pipeline. If the payload looks wrong, reject it and re-prompt with tighter constraints.

Task 3.3 Verify and clean up
  1. Verify the category was created:
    List SSL inspection and URL filtering rule. Confirm it exists and show its contents.
  2. Then delete it:
    Delete the SSL inspection and URL filtering rule created. Confirm before deleting.
  3. Approve the second HMAC confirmation, then re-run the list prompt to confirm the category is gone.
Verify

You completed two HMAC confirmations (create + delete).
