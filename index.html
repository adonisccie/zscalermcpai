Think First · MCP & Security Model
What is the Model Context Protocol (MCP) and how does it let Claude Desktop call Zscaler APIs — without you writing any API or integration code?
Model Context Protocol（MCP）とは何ですか？また、APIや統合コードを一切書かずに、Claude DesktopがZscaler APIを呼び出せる仕組みを説明してください。
See Model Answer

MCP (Model Context Protocol) is an open standard that lets AI models discover and invoke external "tools" at runtime. The Zscaler MCP server exposes Zscaler API calls as named tools (e.g., zpa_application_segment_list, zia_url_filtering_list). Claude Desktop loads the server, reads the tool catalogue, and when you submit a prompt, Claude decides which tool(s) to call, executes them through the MCP channel, and weaves the results into its response. You write no integration code — the MCP server handles authentication, pagination, and API formatting; you just prompt in plain English.

MCP（Model Context Protocol）は、AIモデルが外部の「ツール」を実行時に検出・呼び出すためのオープン標準です。ZscalerのMCPサーバーは、Zscaler APIの呼び出しを名前付きツール（例：zpa_application_segment_list、zia_url_filtering_list）として公開します。Claude Desktopはサーバーを読み込んでツールカタログを参照し、プロンプトを受け取るとClaude自身が呼び出すべきツールを判断してMCPチャネル経由で実行し、結果を回答に組み込みます。統合コードは一切不要——MCPサーバーが認証・ページネーション・APIフォーマットを処理します。あなたは自然言語でプロンプトを入力するだけです。

After you paste your OneAPI credentials into the extension's GUI and click Save, where are they stored — and why does this matter compared to a .env file or claude_desktop_config.json?
拡張機能のGUIにOneAPI認証情報を貼り付けて「保存」をクリックした後、それらはどこに保存されますか？また、.envファイルやclaude_desktop_config.jsonに保存する場合と比べて、なぜそれが重要なのですか？
See Model Answer

The extension stores credentials in your OS keychain — macOS Keychain Access, Linux Secret Service, or Windows Credential Manager. This matters because: (1) the keychain encrypts secrets at rest using OS-level protection tied to your user account; (2) credentials are never written to a plaintext file that could be accidentally committed to a repo or read by another process; (3) the extension retrieves them at runtime without exposing them in environment variables that child processes can inherit. A .env file or JSON config is just plaintext on disk — none of these protections apply.

拡張機能は認証情報をOSキーチェーン（macOSのキーチェーンアクセス、LinuxのSecret Service、WindowsのCredential Manager）に保存します。これが重要な理由：(1) キーチェーンはOSレベルの保護を使用してユーザーアカウントに紐づいた形でシークレットを暗号化保存する；(2) 誤ってリポジトリにコミットされる可能性のあるプレーンテキストファイルや、他のプロセスから読み取り可能な環境変数として公開されることがない；(3) 拡張機能は実行時に認証情報を取得するため、子プロセスに環境変数として漏洩しない。.envファイルやJSONファイルはディスク上のプレーンテキストであり、これらの保護を一切提供しません。

The extension is read-only by default. What additional mechanism protects write operations when you opt into them, and at exactly what point does explicit human accountability enter the loop?
拡張機能はデフォルトで読み取り専用です。書き込み操作をオプトインする際に追加される保護機能は何ですか？また、明示的な人間の責任が生じるのは正確にどの時点ですか？
See Model Answer

When write tools are enabled, the extension surfaces an HMAC confirmation prompt before any change is applied. This shows the exact proposed payload — tool name, target object, and every field being set — and requires your explicit approval. Human accountability enters the loop at this step: you see Claude's intent as a structured payload (not a natural-language description), and you approve or reject before anything changes in Zscaler. Rejecting requires no further action; approving is the authorisation record.

書き込みツールが有効になると、拡張機能は変更を適用する前にHMAC確認プロンプトを表示します。これはツール名・対象オブジェクト・設定されるすべてのフィールドを含む正確なペイロードを示し、明示的な承認を求めます。人間の責任はこの確認ステップで生じます——Claudeの意図が自然言語の説明としてではなく構造化されたペイロードとして提示され、Zscalerへの変更前に承認または拒否します。拒否は追加操作不要；承認がその認可記録となります。

Task 1 — Install the Zscaler Extension in Claude Desktop

~10 min · No terminal, no config files — GUI only.

Task 1.1 Open the Extensions directory

Anthropic and Zscaler ship the Zscaler MCP Server as a one-click Claude Desktop extension. No Docker, no terminal, no config files — just a few clicks and a credential prompt.

AnthropicとZscalerは、Zscaler MCPサーバーをワンクリックで導入できるClaude Desktop拡張機能として提供しています。 Docker不要、ターミナル不要、設定ファイル不要——数回のクリックと認証情報の入力だけで完了します。

  1. Launch Claude Desktop.
  2. Open Settings → Connectors → Customize.
  3. Click Plus (+) icon → Browse Connectors to open the official directory.
  4. Search for Zscaler and select Zscaler MCP Server.
  5. Click Install. Claude Desktop downloads the bundle and opens the configuration screen automatically.
  1. Claude Desktop を起動します。
  2. Settings → Connectors → Customize を開きます。
  3. プラスアイコン (+) → Browse Connectors をクリックして公式ディレクトリを開きます。
  4. Zscaler で検索し、Zscaler MCP Server を選択します。
  5. Install をクリックします。Claude Desktopがバンドルをダウンロードし、設定画面を自動で開きます。
Note

Windows users: the one-click bundle contains packages built for macOS/Linux. On Windows, use the manual config path in the Quick Reference table, then rejoin at Task 1.2.

Windowsユーザーの方へ： ワンクリックバンドルにはmacOS/Linux向けにビルドされたパッケージが含まれています。Windowsの場合は、クイックリファレンス表の手動設定手順を参照し、タスク1.2から再合流してください。

Task 1.3 Scope the tools (recommended)

The configuration screen lets you choose which services and toolsets the extension exposes. Start narrow — you can broaden later. Scoping keeps Claude's context lean and reduces the chance of the wrong tool being chosen.

設定画面で拡張機能が公開するサービスとツールセットを選択できます。 最初は範囲を絞り、後で広げてください。スコープを設定することでClaudeのコンテキストをスリムに保ち、誤ったツールが選択されるリスクを低減します。

  1. In the extension config, set:
    • Services:
      zia, zpa
    • Toolsets:
      zia_url_filtering, zpa_app_segments, zia_url_categories
  2. Save. Leave Enable write tools set to OFF — you'll enable a narrow allowlist in Task 3 if you run the optional write task.
  1. 拡張機能の設定で以下を設定します：
    • サービス：
      zia, zpa
    • ツールセット：
      zia_url_filtering, zpa_app_segments, zia_url_categories
  2. 保存します。書き込みツールの有効化はOFFのままにしてください——オプションのタスク3を実行する場合に限り、許可リストを設定します。
Note

Scoping is both a performance and a safety improvement. Without it, Claude must reason over hundreds of tools across all Zscaler services, slowing tool selection and increasing the risk of choosing the wrong one — entirely separately from the read/write permission model.

スコープ設定はパフォーマンス上の改善であると同時にセキュリティ上の改善でもあります。設定なしでは、Claudeがすべての Zscalerサービスにわたる数百のツールを検討しなければならず、ツール選択が遅くなり誤ったツールが選ばれるリスクも高まります——これは読み取り/書き込みの権限モデルとは完全に独立した問題です。

Task 2 — Operations Made Easy with Prompts

~20 min · Eight prompts across three categories. Read results critically — you are the reviewer.

Task 2A Inventory — what do we have?

Run these three prompts in sequence. Notice that you write no JSON, paginate nothing, and stitch no responses — Claude does that. Your job is to read the output critically.

以下の3つのプロンプトを順番に実行してください。JSONを書く必要も、ページネーションも、レスポンスを繋ぎ合わせる作業も不要——それはClaudeが行います。あなたの役割は出力を批判的に読み評価することです。

Prompt 1 — ZPA application segments

Using the Zscaler tools, list the first 10 ZPA application segments in our tenant. Show name, segment ID, and domain names. Format as a table.

Expected: Claude calls zpa_application_segment_list, parses the response, and returns a clean table — the first "aha" moment vs portal clicking.

期待される結果：Claudeがzpa_application_segment_listを呼び出してレスポンスを解析し、クリーンな表を返します——ポータル操作との最初の「なるほど！」の瞬間。

Prompt 2 — ZIA URL filtering rules

How many ZIA URL filtering rules do we have in total? Group the count by action (block / allow / caution), and tell me which rules are currently disabled.

Expected: A summary table plus a list of disabled rules — what would otherwise require opening every rule individually.

期待される結果：サマリー表と無効なルールの一覧——本来であれば各ルールを個別に開いて確認する必要がある情報です。

Prompt 3 — URL categories filtered by keyword

List ZIA URL categories whose name contains 'AI', 'social', or 'media'. For each, show the category name, type (predefined vs custom), and approximate URL count.

Expected: A focused list. Tests Claude's ability to filter at query time instead of dumping everything.

期待される結果：絞り込まれた一覧。Claudeがすべてを出力するのではなく、クエリ時にフィルタリングできることを確認します。

🧠 Mental Note

MCP = natural language → real API calls, with no glue code from you. Install the extension, paste four credentials, scope to two services, and Claude becomes an interactive interface to your entire ZIA/ZPA estate. Keep it read-only for day-to-day ops. Appendix — Troubleshooting
Extension installs but "no Zscaler tools" 拡張機能はインストールされるが「Zscalerツールなし」と表示される Claude Desktop not fully restarted, or extension disabled. Quit and reopen entirely; check Settings → Extensions. Claude Desktopが完全に再起動されていないか、拡張機能が無効。完全に終了して再起動し、Settings → Extensionsを確認してください。
Config screen rejects credentials 設定画面が認証情報を拒否する Wrong values, or OneAPI not enabled. Re-check four values in Z Identity; confirm with Zscaler account team. 値が誤っているか、OneAPIが有効化されていない。Z Identityで4つの値を再確認し、Zscalerアカウントチームに確認してください。
Tools listed but calls return 403 ツールは表示されるが呼び出しが403を返す Credential lacks required API role. Create/sync a role in the relevant product, link to the OneAPI credential in Z Identity. 認証情報に必要なAPIロールがない。該当製品でロールを作成/同期し、Z IdentityのOneAPI認証情報にリンクしてください。
Write prompt runs but no HMAC confirm appears 書き込みプロンプトが実行されるがHMAC確認が表示されない Write tool not in allowlist, or write toggle is off. Reopen extension config and confirm both settings. 書き込みツールが許可リストにないか、書き込みトグルがオフ。拡張機能の設定を再度開いて両方の設定を確認してください。
HMAC confirm shows wrong payload HMAC確認に誤ったペイロードが表示される Reject the confirmation. Re-prompt with explicit constraints. Never approve a payload you didn't intend. 確認を拒否してください。明示的な制約を加えて再プロンプトしてください。意図しないペイロードを承認しないこと。
